# 零售商品预测与补货工作台

在已有供应链实验上新增的零售场景模块。以门店商品日数据比较预测方法，生成受交期、整箱、库存容量约束的补货建议，并通过批次效期仿真观察满足率与库存权衡。

- [交互界面源文件](index.html)（下载整个模块后通过本地 HTTP 服务打开）
- [Sites 版本](https://retail-demand-planning-mqm.wittlud7.chatgpt.site)（默认仅所有者可访问）
- [固定种子完整结果](results.json)

这是 2026 年 10 月新增的个人作品，借助 AI 实现。全部数据从零合成，无企业原始数据、联系方式、订单或身份映射。不是公司已部署系统，也不证明历史经营收益。

## 运行与复现

需要现代浏览器和 Node.js 20+，无外部 npm 依赖。

```bash
# 仓库根目录
node retail-demo/check.mjs        # 运行有效性检查并打印固定情景结果
node retail-demo/check.mjs --write # 重新生成 results.json
python -m http.server 8000 --directory retail-demo
# 打开 http://localhost:8000
```

浏览器与检查脚本共用 `engine.mjs`，可从门店、商品分类、缺货日处理、交期和补货策略进行探索；支持单商品明细和补货 CSV 导出。CSV 中标明模拟数据及情景设置。

## 数据和评价

固定种子 `20261028`，6 家门店 × 12 个商品 × 210 天，15,120 条记录。短保、冷冻、标品各 4 种；效期、箱规和容量是独立情景参数，不代表行业标准。

- 2026-01-01—06-03：154 天初始历史。
- 2026-06-04—07-01：28 天验证，四个七天起点，以验证期**非缺货销量 MAE**逐组合选择方法。
- 2026-07-02—07-29：28 天测试，四个七天滚动窗口，固定方法、更新历史参数。
- 2026-07-30：承接所选仿真策略期末状态的下一日建议。

三个基础预测方法是 28 日均值、同星期均值、星期与已知促销。另展示验证选模策略，不将其重复算作第四个基础模型。未来星期和促销来自预先定义的日历；生成器也含同类结构，因此促销模型的优势不能外推到真实市场。

约 10% 的历史日由供给事故截断销量。预测可排除带缺货标记的日子，同星期样本不足时退回其他可用历史。排除记录不是对丢失需求的精确恢复，真实场景还可能存在缺货选择偏差。潜在需求 `demand` 只用于测试评分和仿真消耗；预测和选模不读取它。

WAPE 为绝对误差和除以需求和；Bias 为预测总量减需求总量再除以需求总量，正值代表高估。默认情景：28 日均值 WAPE **24.13%**，星期与促销 **22.49%**，验证选模 **23.34%**。验证选模没有超过统一促销模型，保留这一结果，不宣称复杂方案全面更好，也不使用“1-WAPE”包装预测准确率。

## 补货与效期

每日顺序为日初到货、日初下单、满足需求、日末报损和库存记录。下单日为 t、交期为 L 时，订单在 t+L 日初到货。每天复核，目标覆盖当天起 L+1 天。

三类策略使用相同的潜在需求、初始状态、交期和约束：

1. 固定四天覆盖：测试前非缺货历史均值 × 4，覆盖天数固定，交期变化不会自动扩展它。
2. 预测与安全缓冲：保护期预测 + 0.9 × 历史销量标准差 × √保护期。
3. 预测与较高缓冲：同上，系数为 1.8。

系数是对比参数，未校准为名义服务水平；历史销量标准差也不等于累计预测误差。初始库存为测试前历史均值的约两天量、受容量限制。预测策略逐日使用新到的外生销售观测，固定覆盖策略保留测试前日均。模拟库存产生的销量不反馈给预测器，因此是同一外生观测下的策略比较，不是闭环策略学习。

初步订货量为目标库存减现有与在途；向上整箱取整，再以“现有＋在途＋新订单不超过商品容量”的保守约束限制。该容量口径可能过度限制长交期商品，不是共享冷柜或仓储资源模型。

到货批次假设具有完整标称剩余效期，按先到期先出消耗，当日末到期余量计入报损。没有随机交期、运输耗损、临期折价、残值、供应商起订金额、仓库配货限量或审批连接。不含实际采购或补货下单。

默认交期 2 天时：固定覆盖满足率 **96.60%**、平均日末库存 **931.89 件**；安全缓冲策略满足率 **95.25%**、平均日末库存 **616.39 件**；较高缓冲满足率 **96.55%**、平均日末库存 **856.61 件**。降低库存并非没有代价，以上不构成真实成本节约或利润结论。

## 指标与检查

- 满足率：实际满足数量 ÷ 潜在需求数量；不是货架现货率或周期不缺货概率。
- 平均日末库存：各组合测试期日末库存之和 ÷ 28。
- 报损率：到期报损数量 ÷（期初库存＋实际到货）。短保报损少可能来自需求与容量设置，不代表真实业务损耗已解决。
- 在途保留在期末；断货是丢失销售，无欠单。
- 初始库存＋到货＝满足需求＋报损＋期末库存；订单＝到货＋期末在途。

`check.mjs` 检查固定种子、未来数据隔离、隐藏需求隔离、验证选模不读取测试期、864 条库存路径守恒与容量、整箱、筛选分区、空范围和下一日建议约束。检查不是对全部真实业务场景的保证。

## 两分钟演示

1. 打开销量预测，说明模拟数据，比较简单均值、促销方法和验证选模。
2. 筛选一家门店与短保，切到补货页面，对照满足率和平均库存。
3. 把交期从 2 天改到 3 天，解释保护期、容量限制和断货风险。
4. 打开一个商品，核对每日到货、下单、满足、缺货和报损。
5. 导出建议 CSV，指出决策日期、箱规、初步缺口和约束后的建议量。
